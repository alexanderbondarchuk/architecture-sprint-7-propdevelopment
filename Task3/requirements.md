# Требования к безопасности интеграции с платформой «Умный дом»

## 1. Требования к безопасности

### 1.1. Защита передаваемых данных

- Использование **TLS 1.3+** для всех запросов между мобильным приложением, платформой партнёра и backend
- Шифрование трафика между внутренними сервисами PropDevelopment (mTLS)
- Все передаваемые данные должны быть зашифрованы (TLS 1.3+ при передаче, AES-256 при хранении)

### 1.2. Защита персональных данных

- **Соблюдение 152-ФЗ** и требований к защите персональных данных (биометрия, номера автомобилей)
- Биометрические данные должны передаваться и храниться исключительно в зашифрованном виде
- Хранение биометрических данных в РФ в соответствии с ФЗ-152 и ФЗ-210
- Минимизация передаваемой информации: только необходимые атрибуты (user_id, hash-биометрии, номер авто)
- Обезличивание и анонимизация: хранение биометрических данных через хэширование и токенизацию

### 1.3. Контроль доступа

- Внедрение **принципа минимальных привилегий** на всех уровнях: API, БД, доступ к событиям
- Разграничение доступа: доступ только к данным и устройствам конкретных пользователей
- **Белый список IP/доменов** для вызова API платформы партнёра
- Ограничение количества попыток аутентификации и автоматическая блокировка при подозрении на взлом

### 1.4. Аудит и мониторинг

- Все **взаимодействия логируются** на стороне PropDevelopment и платформы
- Логи должны включать: timestamp, user_id, endpoint, результат, ip, fingerprint
- Логирование всех критических операций (открытие двери/шлагбаума, изменение прав доступа)
- В логах не хранить открытые персональные данные
- Регулярный **аудит прав доступа** к функционалу «Умного дома»
- Настройка **алертинга и мониторинга интеграции**: сбои, аномалии, повторы, недоставленные события
- Систематическое проведение аудита использования биометрических данных

## 2. Протоколы аутентификации и авторизации

### 2.1. Механизмы аутентификации

- **OAuth 2.0** для связи между системами (Client Credentials Flow для серверной интеграции)
- **OpenID Connect** для аутентификации пользователей мобильного приложения
- Аутентификация собственников через существующую систему PropDevelopment (Active Directory или Keycloak)
- Для устройств (домофон/шлагбаум) — аутентификация с использованием сертификатов
- **JWT-токены** с ограниченным сроком действия (15-30 минут) для авторизации запросов

### 2.2. Многофакторная аутентификация

- Внедрение **MFA** (SMS, TOTP) для доступа к критическим функциям
- MFA для добавления/удаления устройств

### 2.3. Управление доступом

- **RBAC** (ролевая модель доступа) для владельцев, администраторов, собственников, клиентов, гостей
- Все действия проверяются через роли и разрешения, связанные с конкретной жилплощадью
- Разделение прав для собственников/администраторов/гостей
- Token в HTTPS-заголовке: все авторизационные данные передаются строго в заголовках по HTTPS

## 3. Организация взаимодействия между системами

### 3.1. Архитектурные принципы

- **Single Entry Point** — вход в платформу партнёра только через `smart-home-service`
- **Fail-Safe** — при недоступности API партнёра отображается сообщение пользователю, событие логируется
- **Push-first design** — изменения с платформы приходят через webhook, а не активным опросом
- Интеграция через **API Gateway** для централизованного управления запросами

### 3.2. Технологии взаимодействия

- **REST API** (HTTPS + JSON): App → Backend PropDev → Платформа (открытие двери, управление доступом)
- **Webhooks** (HTTPS + JSON): Платформа → smart-home-service (уведомления о распознавании, входах, ошибках)
- **Синхронизация** через internal REST: tenant-core-app ↔ smart-home-service (обновление прав доступа)

### 3.3. Обработка ошибок и производительность

- Реализация механизма retry с экспоненциальной задержкой для обработки сбоев
- Настройка rate limit
- Мониторинг производительности и доступности внешних сервисов (Prometheus, Loki)
- Отслеживание SLA API, скорости отклика, числа ошибок

## 4. Обязанности партнёра

- Предоставление документации API и схемы авторизации
- Подписание NDA и договора на обработку ПДн
- Проведение аудита безопасности при подключении и ежегодно
- Обеспечение соответствия стандартам защиты данных (ISO/IEC 27001, GDPR, 152-ФЗ)
- Предоставление возможности быстрого отключения интеграции
- Обеспечение регулярного аудита и проверки использования биометрических данных
